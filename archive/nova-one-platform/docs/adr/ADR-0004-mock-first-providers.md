# ADR-0004: استراتيجية Mock-First لمزودات القطع

| الحقل | القيمة |
|---|---|
| الرقم | ADR-0004 |
| الحالة | مقبول |
| التاريخ | 2026-11-12 |
| صاحب القرار | Platform Lead |

## السياق

خطة NOVA-ONE تتطلب حلقة «قطعة تكتب → اختبارات → مراجع مستقل»، لكن بيئة التطوير الحالية بلا GPU وبلا نموذج مستضاف (vLLM/Qwen مؤجلان لحظة توفر العتاد وفق PLAN.md §0.3). الانتظار يوقف كل المراحل — يخالف مبدأ «كل مرحلة تُنتج قطعة قابلة للاختبار».

## القرار

عقد واجهة واحد (`ryko/providers/base.py`) بتنفيذين:

1. **`MockProvider`** — مزود حتمي offline: حلول معروفة بالبذرة، وأعراض فشل قابلة للحقن (إصلاح بعد المحاولة N، مراجع رافض). يُشغّل كل الاختبارات المكثفة وبوابة الانتقال 0 بالأدلة الكاملة بلا شبكة ولا عتاد.
2. **`OpenAICompatProvider`** — عميل OpenAI-Compatible قياسي (يعمل مع vLLM وLM Studio وOpenRouter وغيرها) يقرأ نقطة النهاية والمفاتيح من متغيرات البيئة فقط (`RYKO_LLM_BASE_URL`, `RYKO_LLM_API_KEY`, `RYKO_LLM_MODEL`). التبديل بينه وبين الـMock = تغيير سجل قطع فقط، صفر تغيير في الحلقة.

قواعد إضافية:
- الاستقلالية تُفرض على مستوى `family` القطعة: منفذ ومراجع بنفس العائلة ⇒ رفض فوري قبل أي توليد.
- لا مفاتيح ولا نقاط نهاية في أي ملف ملتزم.

## البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| انتظار GPU ثم البناء | يوقف المرحلة 0/1 كلياً — يخالف المبدأ الحاكم للخطة |
| SDK خارجي (openai pip) | تبعية زائدة لعميل HTTP بسيط — urllib من المكتبة القياسية يفي ويقلل سطح الأمان |
| mock بلا حتمية (عشوائي) | يجعل الاختبارات والأدلة غير قابلة لإعادة التشغيل — يخالف Evidence Gate |

## العواقب

- بوابة 0 تُغلق بالكامل بأدلة حقيقية قابلة لإعادة التشغيل اليوم، والربط الحقيقي بـvLLM لاحقاً لا يغير الحلقة ولا الأدلة ولا الاختبارات.
- قطعة `provider-openai-compat-v1` تبقى `candidate` في السجل حتى تُقيَّم على Holdout حقيقي (حوكمة لا استثناء حتى للبنية التحتية).
