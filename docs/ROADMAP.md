# خطة RYKO الشاملة — ما أُنجز وما بقي، على مراحل

> آخر تحديث: 16 نوفمبر 2026 · نسخة الوثيقة المرتبطة بالإصدار **v1.10.0**
> هذه الوثيقة هي المرجع التنفيذي: كل مرحلة لها ناتج قابل للقياس وبوابة قبول،
> وكل رقم هنا مأخوذ من تشغيل فعلي موثق في `docs/results/`.

## 0) الموقع الحالي في سطر واحد

Ryko اليوم **أنبوب كامل قابل لإعادة الإنتاج** (كوربوس ← رمزنة ← تدريب ← تقييم
← خدمة ← إيصالات provenance) بمدونة تراثية **v4 = 217.7 مليون توكن** (تنظيف
بثّي بذاكرة ثابتة، حذف 1.46M فقرة مكررة) ونموذج Ryko-Tiny (11.5M معلم):
ارتباكه على تحقق v3 انخفض **من 504.7 إلى 160.4 (3.15×)**، ثم **من 139.0 إلى
114.3 على تحقق v4** بعد الاستمرار الإحمائي على المدفوعة الأنظف.

**مصادر المدونة الحالية (كلها مجانية وموثقة المصدر):**

| المصدر | الحجم في v3 | الملاحظة |
|---|---|---|
| ويكيبيديا العربية (20231101) | شرائح عميقة | عربية حديثة |
| تكشيلة (arbml/tashkeela) | كامل تقريباً | تراث مُشكَّل، أزيل التشكيل |
| OpenITI 2023.1.8 (HF mirror) | شظايا 0–1 من 7 = 1,782 كتاباً | تصلح لإضافة 5 شظايا بقية |
| Shamela v4 (AuthenticIlm) | 144 كتاباً مختاراً | `pages.jsonl` لكل كتاب: page_num + book_id = provenance جاهز |

**ما أُضيف هذا الإصدار كأدوات (وليس بيانات فقط):**

- `ryko_lm.data.collect_openiti` — بثّ شظايا parquet + تنظيف mARkdown، قابل للاستئناف.
- `ryko_lm.data.collect_shamela` — اختيار طبقي لكتب مشهورة + تنزيل متوازٍ + سجل تقدم.
- `ryko_lm.data.augment_corpus` — توسيع تدريجي بذاكرة ثابتة: بصمات FNV/int للفقرات،
  إزالة تكرار عالمية، دمج old+new دون إعادة تنظيف الكل.
- `ryko_lm.eval.evaluate` — بروتوكول تقييم **حتمي** (نوافذ متتالية غير متداخلة، بلا RNG)
  + توليد موحد البذور + خيار كبح EOS لعينات الطلاقة.
- `ryko_lm.provenance` — **إيصالات sha256 قابلة للتحقق دون اتصال** (نمط ZYKO):
  `python -m ryko_lm.provenance make|verify`.
- `ryko_lm.serving.guard` — **حارس ما قبل التسليم**: نسبة عربية، حلقات تكرار،
  بقايا markup، قرار ALLOW/REVIEW مختوم بهاش (نمط ZYKO guardian).
- `ryko_lm.training.export` — تصدير last.pt ← final.pt بصيغة الخدمة (fp16 + تكوين).

## 2) المراحل المتبقية (مرتبة بالأولوية وبوابة قبول لكل مرحلة)

### المرحلة 3 — إكمال جدولة التدريب (أولوية قصوى، بلا حوسبة جديدة)
- **العمل:** إعادة تشغيل نفس الأمر حتى اكتمال الـ 20,000 خطوة (82M توكن).
  التدريب قابل للاستئناف بالضبط من `artifacts/training_v3/last.pt`:
  ```bash
  python -m ryko_lm.training.train --config configs/models/ryko-tiny.yaml \
      --data-dir data/processed_v3 --out-dir artifacts/training_v3 \
      --total-steps 20000 --batch-size 16
  ```
- **بوابة القبول:** val_loss < 4.8 (PPL < 125 تقديرياً) على بروتوكول
  `ryko_lm.eval.evaluate` الكامل، وsummary.json مكتوب.
- **الحالة بعد v1.6.0:** محققة على مسار الاستمرار الإحمائي — تدرّب على
  `data/processed_v4` (217.7M توكن) بدءاً من أوزان v3: **1,750 خطوة (+7.17M
  توكن، 28.5M فعلي)**، val_loss **4.739 (PPL 114.3)** وأفضل نقطة 4.645
  (PPL 104.1) عند الخطوة 1500 — بوابة PPL < 125 **منجزة**، والبوابة الكاملة
  (20 ألف خطوة على v3 أو ما يعادلها على v4) تتقدم مع كل جلسة حوسبة.

### المرحلة 4 — توسيع البيانات إلى الكمال (متوازٍ مع 3)
- **الحالة بعد v1.6.0:** مدفوعة v4 مبنية بتنظيف بثّي بذاكرة ثابتة (34,851
  مستنداً: ويكيبيديا 2,437 + تشكيلة 24,400 + شاملة 144 كتاباً + OpenITI 1,783
  كتاباً) = 782.1M حرف ← **217.7M توكن** بعد حذف 1,458,904 فقرة مكررة، مع
  إيصال provenance موقّع. الباب مفتوح لتوسيع أكبر بلا حدّ ذاكرة.
- **العمل المتبقي:** شظايا OpenITI 2–6 (≈1.1GB إضافية ≈ +250M توكن خام)، ورفع اختيار
  Shamela من 144 إلى 500 كتاب (`--per-cat 12`)، وتكملة شرائح ويكيبيديا الأعمق.
- **بوابة القبول:** مدونة ≥ 500M توكن بعد إزالة التكرار، وإيصال provenance جديد.
- **ملاحظة ترخيص:** OpenITI CC-BY-SA للرقمنة على نصوص ملك عام؛ Shamela معلنة MIT
  مع تحفظ حقوق التحقيق — نحتفظ بحقل `rights_status` في قاعدة المعرفة (المرحلة 6).

### المرحلة 5 — ryko-small على GPU (بعد 3+4)
- **العمل:** تدريب `configs/models/ryko-small.yaml` (52.2M معلم، ctx 512) على
  المدونة الموسعة؛ جدولة cosine كاملة من الصفر.
- **بوابة القبول:** PPL < 60 على نفس مجموعة التحقق، وتحسن ظاهر في اتساق
  الإسناد والفقه في العينات المبذورة.

### المرحلة 6 — RYKO Knowledge Core (قاعدة المعرفة)
- **العمل:** تحويل إثبات المصدر الموجود فعلاً (book_id/page_num في بيانات
  Shamela، معرّفات كتب OpenITI) إلى مخطط PostgreSQL: جداول `sources`, `books`,
  `passages`, `claims`, `argument_relations` (المخطط في بحث RYKO المرفق)، مع
  pgvector للبحث الدلالي وBM25 نصي.
- **بوابة القبول:** كل مقطع يمكن إرجاعه إلى كتاب + صفحة + بصمة sha256؛
  إيصال provenance لكل دفعة استيراد.
- **الحالة:** ✅ **v1.3.0 سلّم الأساس المحلي** — مخطط SQLite للجداول الستة
  (`ryko_lm.knowledge`)، استرجاع هجين حتمي (BM25 + hashing-embeddings + RRF)،
  مدقق اقتباس، بذرة 10 كتب / 11,674 مقطعاً بإسناد صفحي وإيصال متحقق.  الباقي:
  خادم PostgreSQL + pgvector عند التوسع، وتضمينات دلالية عربية حقيقية.
- **هذا هو الأساس للـ RAG الموثق قبل أي ضبط دقيق.**
- **الطبقات المنقوحة فوق الأساس:** طبقة الفكر المنقح v1.7.0/v1.8.0
  (`docs/ISLAMIC_THOUGHT.md`) وطبقة الاقتصاد والحقوق v1.9.0
  (`docs/ECONOMICS_RIGHTS.md`) — كل طبقة = مانيفست بسياسة نطاق مفروضة
  آلياً + كتب مُنسَّقة بإثبات صفحة + أفكار بإسناد، وعزل طبقات مختبر.
  وفوقها رسم علاقات الحجاج v1.10.0: 35 علاقة موثقة بين الأفكار
  (`argument_relations` + `GET /knowledge/relations`).

### المرحلة 7 — بوابات التقييم العلمي
- **العمل:** تشغيل ISTB (3,465 سؤالاً) وFiqhQA (قياس الامتناع) وIslamicFaithQA
  على نقاط النهاية بعد المرحلة 5، وبناء معيار داخلي `RYKO-Bench` (1,000 حالة
  كما في البحث المرفق: بحث قول/دليل/اعتراض/ترجيح/امتناع).
- **الحالة:** ◐ **v1.4.0 بنى المنصة والبذرة** — عقد `ryko-bench/1`، عدّاء
  حتمي للقدرات الثلاث، بذرة 56 حالة ذاتية التحقق من نواة المعرفة، وخط أساس
  منشور.  الباقي: تنزيل ISTB/FiqhQA الكاملة وتشغيلها بعد المرحلة 5، وتوسيع
  البذرة إلى 1,000 حالة بمراجعة بشرية.
- **بوابة القبول:** تقرير لكل قدرة على حدة (لا رقم واحد جامع)، ونشر النتائج
  في `docs/results/benchmarks.md`.

### المرحلة 8 — Ryko × ZYKO (البرمجة العربية)
- **العمل:** الربط بين المشروعين: Ryko يفهم الطلب العربي (NLU) وZYKO يولّد
  الكود حتمياً ويراجعه (38 قاعدة AST + حارس + إيصالات). الحزمة المستفادة فعلاً
  في v1.2.0: نمط الإيصالات (provenance) ونمط الحارس (guard) — والمرحلة القادمة
  بوابة `arabic-prompt → zyko pipeline` مع SFT على أزواج (تعليمات عربية ← كود).
- **بوابة القبول:** أمر عربي واحد ينتج كوداً يمر بحارس ZYKO ويتحقق `zyko verify`.

### المرحلة 9 — المحاذاة والنشر
- **العمل:** SFT على مهام الفهم التراثي ثم DPO بعينات تفضيل (إجابة موثقة
  بأدلة مقابل إجابة واثقة بلا سند)، ثم نشر النقاط على Hugging Face Hub.
- **بوابة القبول:** تحسن قابل للقياس على RYKO-Bench دون تراجع ISTB.

## 3) القرارات الهندسية الثابتة

1. **لا نغيّر الرمّاز** (32K Byte-Level BPE) إلا بتجربة MorphBPE/CAMeL موثقة
   تُظهر مكسباً في المهام — تغيير المفردات يعني إعادة تدريب كاملة.
2. **الاستئناف بالضبط** شرط للبنية: كل جلسة تدريب يجب أن تُغلق بحفظ `last.pt`.
3. **كل رقم يُقاس ببروتوكول حتمي واحد** (`ryko_lm.eval.evaluate`، نوافذ متتالية
   كاملة) — أي رقم بروتوكول آخر لا يُقارن.
4. **كل أصل (corpus/checkpoint) يحمل إيصالاً** موقّعاً قبل الإعلان عنه.
5. **الأمانة العلمية أولاً:** النموذج لا يُقدَّم كمرجع شرعي؛ التقييم يفصل
   الامتناع عن الهلوسة، والبوابات تُقبل/تُرفض بالأرقام لا بالانطباع.

## 4) أوامر نواة المعرفة (المرحلة 6 — v1.3.0)

```bash
python -m ryko_lm.data.collect_shamela --per-cat 1 --max-books 12 --max-file-mb 3 \
    --keep-pages --out data/raw/shamela_knowledge.jsonl          # جلب بإسناد صفحي
python -m ryko_lm.knowledge ingest --format shamela \
    --jsonl data/raw/shamela_knowledge.jsonl --db data/knowledge/ryko.sqlite
python -m ryko_lm.knowledge search --db data/knowledge/ryko.sqlite "استعلامك" -k 5
python -m ryko_lm.knowledge cite   --db data/knowledge/ryko.sqlite "نص الاقتباس"
python -m ryko_lm.knowledge ideas  --db data/knowledge/ryko.sqlite "استعلامك" --layer econom
python -m ryko_lm.knowledge relations --db data/knowledge/ryko.sqlite --layer fikr
python -m ryko_lm.security.secret_scan --tree .                   # بوابة الأسرار
```

أو عبر Makefile: `make knowledge-ingest` · `make knowledge-search Q="..."`
· `make knowledge-cite Q="..."` · `make knowledge-receipt` · `make secret-scan`.
التفصيل الكامل في `docs/KNOWLEDGE_CORE.md`.

## 5) كيف تساهم في المرحلة 3 الآن (سطران)

```bash
python -m ryko_lm.training.train --config configs/models/ryko-tiny.yaml \
    --data-dir data/processed_v3 --out-dir artifacts/training_v3 --total-steps 20000 --batch-size 16
```
