# ADR-0002: السلامة كود حتمي — مصدر واحد يولّد Python وDart

| الحقل | القيمة |
|---|---|
| الرقم | ADR-0002 |
| الحالة | **مقبول** (قرار معماري ملزم — القسم 1.3 من الوثيقة الهندسية) |
| التاريخ | 2026-11-12 |
| صاحب القرار | Backend-1 + القائد السريري (العتبات ⚠) |

## السياق

بوابة الخطر تعمل في مكانين: الخادم (Python) وعلى الجهاز بلا إنترنت (Flutter/Dart). أي انفصال بين منطقي التقييم يعني أن الجهاز والخادم قد يعطيا قرارين مختلفين لنفس الحالة — خطأ سلامة قاتل في منتج صحي. التعديل اليدوي المزدوج مصدر انزياح دائم.

## القرار

- قواعد الخطر والقيم الحرجة تُكتب مرة واحدة بصيغة YAML آلية في `safety/rules/*.yaml` مع كتلة توقيع سريري لكل قاعدة.
- مولّد واحد (`safety/codegen/generator.py`) يولّد `services/safety/rules_generated.py` و`mobile/medai_app/lib/safety/rules_generated.dart` من نفس الحمولة الموحدة (Canonical JSON) — مطابقة بايت-ببايت.
- `make parity` يفشل البناء عند أي انحراف بين الطرفين، و`make golden-check` يضمن قابلية إعادة إنتاج المجموعة الذهبية بايت-ببايت (بذرة 42).
- أي شرط غير قابل للتقييم لا يُطلق قاعدة (فشل آمن)، والقرار النهائي عبر `triage_decision` وفق عقد `contracts/v1/triage.schema.json`.

## البدائل المرفوضة

| البديل | سبب الرفض |
|---|---|
| كتابة القواعد مرتين يدوياً (Python وDart) | انزياح حتمي مع كل تعديل — ممنوع بموجب القسم 1.3 |
| محرك قواعد خارجي (Drools/JSON-LD) | تبعية ثقيلة وتعقيد تحقق سريري؛ v0 يبقي المولد داخلياً وقابلاً للتدقيق |
| بوابة خطر خادمية فقط | يخالف اشتراط العمل offline أولاً على الجهاز |

## العواقب

- كل تعديل عتبة = تعديل YAML فقط + إعادة توليد + تمرير البوابات + توقيع سريري جديد للإصدار.
- التكافؤ السلوكي الكامل (تشغيل فعلي على Dart VM لـ1000 حالة عشوائية) يُستكمل عند توفر Dart SDK في CI — حالياً يتحقق CI من تكافؤ الحمولة والمنطق المولد مراجعةً.
