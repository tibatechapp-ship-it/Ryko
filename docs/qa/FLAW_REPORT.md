## قائمة العيوب

### F1 — completion فارغ بلا إشارة امتنان في الخدمة (major — **مُصلَح في تحضير v1.27.0**)
`/generate` يردّ 200 مع `completion=""` و`generated_tokens=1` عندما يطلق
النموذج EOS في أول رمز، بلا حقل `abstained` أو أي تمييز بين «امتناع» و«خلل».
امتنان العدّاء داخلياً بوابة ثقة على الخيارات (0.65) لا EOS — فسلوك الخدمة
الصامت هذا غير موثق كعقد، ومع بذرة القياس المنشورة (315) انهارت كل عبارات
الفحص العشر إلى الصمت، بما فيها الداخلية منها.
إعادة الإنتاج:
```
PYTHONPATH=src python -c "
from fastapi.testclient import TestClient
from ryko_lm.serving.api import app
with TestClient(app) as tc:
    print(tc.post('/generate', json={'prompt':'ما هو الحديث الذي ورد في فضل الصدق؟','max_new_tokens':8,'seed':315}).json())
# → completion '' و generated_tokens 1؛ وبذرة 999 تنتج نصاً
"
```
التوصية: حقل صريح (`abstained: true` أو نص امتنان موحد) أو توثيق دلالة
السلسلة الفارغة في عقد الـ API.

**الحالة: مُصلَح (الوكيل 5 — بوابة الجودة النهائية، تحضير v1.27.0).**
إصلاح إضافي بلا كسر للعقد: `/generate` يُرجع الآن في كل رد حقلين جديدين
`abstained` (bool) و `finish_reason` (`"eos_immediate"` عندما `completion`
فارغ و `generated_tokens ≤ 1`، وإلا `"stop"`) — الحقول الإضافية لا تكسر
العملاء القائمين. التحقق: اختبار جديد
`test_generate_reports_immediate_eos_abstention` في `tests/test_serving.py`
يثبت السلوك ببذرة 315 المنشورة (الإكمال '' و generated_tokens=1)، وتأكيد
المسار المعاكس أُضيف إلى `test_generate_endpoint`؛ أُعيد تشغيل
`tests/test_serving.py`: ‏7 passed. ملاحظة: `/generate/stream` تُرك كما هو
(التحسين الممتد يُؤجَّل) والامتنان المُعايَر للعدّاء يبقى بوابة الثقة 0.65
لا EOS — هذا الإصلاح يخص قابلية الرصد عند المستدعي فقط.

### F2 — عدم حتمية المسار الافتراضي بلا بذرة (minor — **مفتوح**)
بلا `seed`، العبارة نفسها تنتج بين جواب وصمت من استدعاء لآخر
（temperات 0.8 افتراضية)؛ مقبول عينياً كعينات، لكنه مركّب مع F1 يجعل نسبة
الردود الفارغة مرتفعة بلا سبب ظاهر للمستدعي.
**المعالجة المقترحة (مفتوحة):** توثيق أن النداء بلا `seed` = عينة عشوائية
مقصودة، وتشجيع العملاء على تمرير بذرة عند الحاجة للحتمية؛ لا تغيير كود.

### F3 — سقف 2000 حرف صارم مقابل ميزانية 512 رمزاً (minor — **مفتوح**)
`GenerateRequest` يرفض (422) كل ما فوق 2000 حرف، بينما block_size=512 يعني
أن ميزانية الإدخال الفعلية ~500 رمز (1,972 حرفاً ≈ 479 رمزاً); مستند أطول
من ذلك يُرفض كلياً بلا تقطيع أو تجزيء من الخادم. الكمون عند الحد ممتاز
(0.55s لسقف 200 رمز).
**المعالجة المقترحة (مفتوحة):** الأقل كلفة — توثيق سقف 2000 حرف ومبرره
الرمزي في عقد الـ API مع رسالة 422 أوضح؛ التقطيع التلقائي يُؤجَّل
(قرار معماري لا يُفرض في بوابة الجودة).

### F4 — انجراف استمراري نحو أطر اقتباس مُختلقة (minor / جودة — **مفتوح**)
مخرجات الجيل الحر تنزلق إلى أطر اقتباس مُفبركة ("﴿حذف، أي: صاعوا."،
"وأنشد أبو عبيد:") — متسق مع مقايضة المحاذاة المنشورة (val PPL 165.5 ←
247.6)؛ يُسجّل في دفتر الأمانة لا كتراجع جديد.
**المعالجة المقترحة (مفتوحة):** لا معالجة قبل جلسة GPU — مرشح معالجة
طبيعي هو إعادة موازنة DPO بأفضليات دفاعية (3د في الخطة)؛ يُقاس بعد
v1.27.0.

### F5 — تباين تسمية الحقول بين `/generate` و`/generate/stream` (minor/info — **مفتوح**)
الجيل غير الممتد يرجع `completion` والبث يرجع `text`، و
`generated_tokens` تعدّ الرموز الجديدة فقط (عقد الاختبارات) — يُستحسن
توثيقها لتجنب لبس المستدعي.
**المعالجة المقترحة (مفتوحة):** ملاحظة تناغم تسمية في عقد الـ API الآن
(‏`completion` = الجيل غير الممتد، `text` = البث الجاري)، والتوحيد الفعلي
يُؤجَّل لتجنب كسر العملاء القائمين.
