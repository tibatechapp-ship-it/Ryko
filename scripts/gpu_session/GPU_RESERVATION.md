# حجز جلسة GPU — الدليل العملي (v1.28.1)

> التنفيذ نفسه موحّد في أمر واحد: `scripts/gpu_session/run_session.sh`
> (المنفّذ الحرفي لـ`docs/GPU_SESSION_PLAN.md`). هذه الصفحة عن **الحجز** فقط:
> ما قبل الجلسة، وما خلالها، وما بعدها.

---

## 1) من يحجز؟ (الحدود الصادقة)

بيئة التطوير الحالية (الساندبوكس) **CPU فقط** (`torch+cpu`، لا `nvidia-smi`)
وبلا صلاحيات فوترة — فالحجز نفسه فعل بشري خارج هذه البيئة. كل ما قبله وما
بعُه مُتم عبر الحزمة الملتزمة: طليعة §2 أخضر كامل (649+1 اختبار، إيصالات 17/5
المتوقعة، بايتات مطابقة)، والجلسة نفسها أمر واحد.

## 2) المواصفة المطلوبة (§1 — لا أقل منها)

| البند | القيمة | ملاحظة |
|---|---|---|
| GPU | واحد، **≥24GB VRAM** | A100 40GB مثالي؛ RTX 4090 24GB كافية |
| مصفوفة logits | 2.15GB/نسخة عند batch 32 (32×512×32768 fp32) | تناسب 24GB بمعلم 52M |
| عند OOM | ذراع معتمدة: `OOM_ARM=8 bash scripts/gpu_session/run_session.sh` | ≈4.8 حقبة بدل 19.1 |
| قرص حر | ≥6GB | الحزمة ~1.1GB + نقاط ~0.6GB + سجلات |
| زمن متصل | **≥6 ساعات** تُنجز الجلسة كلها | 5أ ~2–4.5h + 5ب ~20m + 6أ/6ب ~25m + الرباعي ×2 ~1h |
| جلسات أقصر | مقبولة: `TIME_BUDGET=3300` يوقف بسجلة عند الحد، والاستئناف = إعادة نفس الأمر | §3أ — بلا فقد |
| بايثون | 3.11 أو 3.12 (الشيفرة مُتحقق منها على 3.11 ببوابة CI + حارس `check_py311_fstrings.py`) | |

**قياس مثبت (2026-11-21، `docs/results/gpu_session/HW_CEILING_VERDICT.md`)**:
بيئة تطوير 2 vCPU/3GB بلا CUDA اقتلها النواة OOM عند batch 8 و4 (SIGKILL 137)،
وتسير على batch 2 بـ444 توكن/ث ⇒ جرعة العقد = 410+ ساعة CPU — المرحلة 5أ
مقيدة بـGPU قياساً. أول مرساة مقاسة «قبل»: PPL الخدمة على المسطرة = 314.96.

## 3) أين يحجز؟ (خيارات — بلا أسعار مُختلَقة، قارن الحالية وقت الحجز)

| المزوّد | ماذا يوفر | ملاحظة تشغيلية للجلسة |
|---|---|---|
| **RunPod** | A100/4090 بالساعة، Jupyter/SSH | الأنسب لجلسة ≥6h واحدة؛ PAYG |
| **Vast.ai** | سوق بطاقات بالساعة (غالباً الأرخص) | تحقق من استمرارية المثيل قبل الجلسة |
| **Lambda Cloud** | A100/H100 سحابية، بلاطات ثابتة | فاتورة شهرية؛ يتطلب تحقق حساب |
| **Google Colab (Pro/Pro+)** | A100/T4 من المتصفح | T4 (16GB) → استعمل `OOM_ARM=8`؛ مهلة الجلسة أقصر — اعتمد الاستئناف |
| **Kaggle Notebooks** | T4/P100 مجانية (~12–16GB) | مجانية فعلاً لكن المهلة ~12h/جلسة: `TIME_BUDGET` + استئناف، وP100 16GB تتحمل batch 32 غالباً |
| **AWS/GCP/Azure** | مثيلات GPU بلاطات | إذا كان لديك رصيد مؤسسي |

**القاعدة**: أي بطاقة ≥24GB تُنجز الجلسة بالجرعة الحرفية؛ 16GB تشتغل على
ذراع OOM الموثقة (`OOM_ARM=8`) وتعطي نفس البوابات بزمن أطول (~0.75–1.5h
لـ5أ فقط — انظر حساب §1).

## 4) بدء الجلسة — أربع أسطر (نسخ حرفي على آلة الجلسة)

```bash
git clone https://github.com/tibatechapp-ship-it/Ryko && cd Ryko
pip install "torch>=2.2" --index-url https://download.pytorch.org/whl/cu121 \
    || pip install "torch>=2.2" --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
bash scripts/gpu_session/run_session.sh
```

السكربت نفسه يفرض طليعة §2 على آلة الجلسة (sha256 نقطة الخدمة والرمّاز،
إيصال `processed_ling` PASSED، قرص ≥6GB، الاختبار الكامل، imports) قبل
صرف **أي دقيقة GPU** — أي انحراف = إجهاض مبكر برسالة سبب.

> ملاحظة §2.3: إيصال `data/processed_ling` يتطلب الباينات الثقيلة خارج git.
> على آلة الجلسة: إما `make lugha-collect ling-pack ling-pack-binarize` ثم
> إعادة توقيع الإيصال بعد binarize (`provenance make` — النمط الموثق)، أو
> نقل `train.bin`/`val.bin` من بيئة موثوقة — البايتات هي العقد لا طريقة النقل.

## 5) أثناء الجلسة وبعدها

- **السجل**: كل شيء أمامي (foreground) يُكتب في `docs/results/gpu_session_<ts>.log`.
- **الاستئناف**: أعد تشغيل نفس الأمر؛ الخروج `3` = توقف نظيف محفوظ.
- **التشغيل المزدوج** (§5.5) يُفرض آلياً — أي عدم تطابق = توقف قبل النشر.
- **القرار** يُطبع آلياً من جدول §4.1+§4.2:
  - exit `0` ⇒ قائمة الترقية §6 كاملة بالقيم الفعلية (ثابتا الحارس + conftest + api + ROUTING + CHANGELOG + وسم بعد `make secret-scan` — دون push).
  - exit `1` ⇒ document-and-hold §7.1: الدفتر مؤرشف في `docs/results/gpu_session/` + `index.json` (sha256)، والأذرع الجاهزة معروضة (جرعات، أفضليات، β/lr، WiSE-FT تشخيصاً فقط).
  - exit `2` ⇒ التوأم نفسه غير مكتمل — مراجعة جرعة الأساس أولاً.
- **ما يُلتزم بعد الجلسة**: ملفات JSON للرباعي + `index.json` + سجل الجلسة (نمط `bundle_experiments/`). نقاط `.pt` الثقيلة تبقى خارج git مع إيصالاتها الموقعة.
